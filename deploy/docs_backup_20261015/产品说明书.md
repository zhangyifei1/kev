# Kev-4B 产品说明书

> 内网部署版本,服务地址 `http://10.94.1.8:8009`(Docker 容器 `kev-4b`,固定 1 号 GPU 卡)

## 一句话介绍

Kev-4B 是一个**决策判断服务**:给它一段背景材料(政策、合同、对话记录、评审规则……)和一批问题,它一次性返回所有问题的判断结果和置信度。它**不生成文本、不解释理由**,只输出结构化判断——因此非常快(单题毫秒级),也因此在产品上要把它当"打分器"用,而不是当"问答助手"用。

## 适合的场景

| 场景 | 用法 | 问题类型 |
|---|---|---|
| 合规/政策检查 | 把制度条文放 state,问"这个操作是否违反政策" | noul(是/否) |
| 内容审核初筛 | 把待审内容放 state,按审核标准打分或分类 | score / choice |
| 工单/评论自动分类 | 把工单内容放 state,从预设类别里选 | choice(多选一) |
| 方案评审 | 把评审标准放 state,对每个候选方案打分 | score(1~5 级) |
| 质量抽检 | 把质检规则放 state,对样本逐条判断 | noul / choice |
| 大批量材料预审 | 每份材料一个 state,挂几十个检查项一次问完 | 混合,一次请求最多不限题数 |

**不适合的场景**:开放问答(它会拒绝,因为不是生成模型)、需要引用原文出处的判断(它只给概率不给理由)、比 state 上限(65,536 token)更长的材料(会被 422 拒绝)。

## 三种问题类型

所有问题都挂在同一段背景材料(state)上,一次请求可以混合三种类型:

### 1. noul —— 是/否判断

返回"是"的概率(0~1)。**> 0.5 倾向"是",< 0.5 倾向"否"**,越接近 0 或 1 越确定,0.5 附近表示拿不准。

```json
{"type": "noul", "text": "提前5天订票符合差旅政策吗?"}
```
```json
{"q1": {"type": "noul", "noul": 0.4019}}
```

`instructions` / `criteria` 可选,用来补充判定标准(如 `criteria.true`: "符合", `criteria.false`: "违反")。

### 2. choice —— 多选一

`criteria` 是选项字典,返回:选中的选项 `choice`、完整概率分布 `probabilities`、置信度 `confidence`(0~1)。

```json
{"type": "choice", "text": "这个工单属于哪个类别?", "criteria": {"bug": "功能故障", "billing": "费用争议", "other": "其他"}}
```
```json
{"q1": {"type": "choice", "choice": "billing", "confidence": 0.62,
        "probabilities": {"bug": 0.11, "billing": 0.73, "other": 0.16}}}
```

### 3. score —— 分级评分

`criteria` 是**按等级顺序**排列的描述数组,返回期望等级 `score`(如 2.4 代表"介于 2 级和 3 级之间")、每个等级的概率、置信度。

```json
{"type": "score", "text": "评估这条回复的语气友好程度", "criteria": ["很敌对", "冷淡", "中性", "友好", "非常热情"]}
```
```json
{"q1": {"type": "score", "score": 2.83, "confidence": 0.41,
        "legend": {"0": "很敌对", "1": "冷淡", "2": "中性", "3": "友好", "4": "非常热情"},
        "probabilities": {"0": 0.02, "1": 0.18, "2": 0.49, "3": 0.26, "4": 0.05}}}
```

## 怎么用置信度(confidence)

- **choice / score** 返回 0~1 的 confidence:0 = 完全均匀分布(拿不准),1 = 概率全部集中在一个选项(非常确定)。
- **noul** 没有 confidence 字段,`noul` 值离 0.5 的距离就是它的确定程度。
- **建议的产品策略**:confidence 高于阈值(如 0.4)直接自动化;低于阈值转人工复核。阈值应该在你们自己的业务数据上标定,不要照抄。

## 容量与性能(本部署实测)

| 指标 | 值 |
|---|---|
| 单请求延迟(短材料,单题) | **~230 ms** |
| 一次请求的问题数 | 不限(一次 prefill 全部算完) |
| state 长度上限 | 65,536 token(约 4~8 万汉字) |
| 单题上限 | 8,192 token |
| 选项数上限 | 255 |
| 显存占用 | 25.7 GiB / 32 GiB(V100-32G 独占) |
| 并发 | 服务内部自动组批;高并发场景联系部署方压测 |

## 使用须知(重要)

1. **没有文本生成**:Kev 的输出只有概率和判断,不会有"因为……所以……"。需要解释就自己写规则引擎,把 state 组织得更结构化。
2. **概率不是概率论意义上的保证**:温度校准过的模型,ECE(期望校准误差)在训练分布上 ~0.02,但跨领域不保证。上自动流程前,先在你们自己的样本上抽检校准。
3. **中文可用但以英文语料训练为主**:判断类任务(政策符合性、分类、评分)中文表现良好;极专业的中文术语建议在 `criteria` 里给出明确定义。
4. **材料越相关越好**:把判定需要的所有事实放进 state,别指望模型外部知识。长材料中埋藏的关键信息建议放在 state 前部或明确标注。
5. **服务无人值守**:容器 `restart: unless-stopped`,宕机自愈;但宿主机或 GPU 故障需要人工介入。

## 快速上手

curl 版:

```bash
curl -X POST http://10.94.1.8:8009/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{
    "state": {"政策": "经济舱需提前7天预订,住宿每晚400元以内"},
    "questions": {
      "合规": {"type": "noul", "text": "提前5天订经济舱符合政策吗?"},
      "等级": {"type": "score", "text": "该行为违规程度", "criteria": ["无违规", "轻微", "严重"]}
    }
  }'
```

返回:

```json
{"model":"kev-latest",
 "answers":{"合规":{"type":"noul","noul":0.4019},
            "等级":{"type":"score","score":1.9,...}},
 "usage":{"input_tokens":44,"output_tokens":71},
 "latency_ms":232.0}
```

Python 版见《接口文档》。
